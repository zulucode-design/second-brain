Issue #167 — the harness restores the Windows window state

2026-09-29. On Windows the alpha harness journaled only %APPDATA%\io.github.zulucodedesign.SecondBrain\config.json. Every launch of the installed app also writes .window-state.json in that folder through tauri-plugin-window-state, and nothing put it back. After the candidate 96a3e5b runs, the real profile held an off-screen window position and a compact size, and it was restored by hand.

Fix

StepChange in scripts/alpha-harness.mjs
prepare Copies .window-state.json to original-window-state.json in the run directory with its SHA-256, or records that it did not exist. The paths and the hash go into the run's journal, and the prepared evidence event carries the hash.
finalize and recover Wherever config.json is restored, the window state is restored too, or removed if the run created it. The worker then hashes the live file and fails unless it has the pre-run hash. It compares with the recorded hash, not the journal copy, so a damaged copy also fails. It returns that hash (windowStateSha256, null when the file is absent). The controller records it in the config-restored evidence event after finalize and in stale-run-recovered after recover. Both results also carry windowStateJournaled, which tells a journal from before this change apart from an absent file.
finalize after recover When the lock is already gone, the same comparison runs, as it does for config.json.
Older journals A journal written before this change has no window-state fields; its runs are recovered as before, with nothing to restore.

A new test in tests/alpha-harness.test.mjs covers both cases (file present and changed; file absent and created by the run), the failing comparison before restore, a damaged journal copy, and an older journal, which is neither restored nor checked.
