Each disposable replica contains 5,000 deterministic notes and an 8 MiB attachment. The existing tauri-driver harness drives Settings > Backup and Settings > Sync in the installed applications. Fedora uses isolated XDG directories. Windows journals and restores the original config, routes a fresh vault identity to disposable machine state, and preserves the original window-state bytes. The app's Syncthing instances pair over Tailscale. No production vault is opened.

Initial convergence precedes the acceptance batches. Each of six incoming rounds edits a different note on each peer. Every new ZIP is compared member by member with hashes captured before the batch; the receiver must then contain the peer's new bytes. Retention is selected as 5 through the Backup UI. One manual backup is created before the incoming rounds. Initial-convergence archives are retained separately from this retention pool.

For the failure check, both peers have fresh outgoing changes. A disposable Fedora backup directory has mode 0555; a disposable Windows directory denies the running account write access. The saved backup-folder setting substitutes for the native directory picker, which WebDriver cannot answer. Sync itself is triggered by its visible UI button. Settings and directory permissions are restored afterwards.

Routine sync timing

Archive write time is the ZIP's filesystem creation time through its final modification time. It measures archive creation, not peer connection or the later convergence/hold phases. Total batch time runs from the Sync now click to that machine's successful sync-done event. Both timestamps in each duration come from the same machine; cross-machine clock alignment is not assumed. Initial convergence is excluded.

Accepted budget: at most 2 seconds to write each pre-sync ZIP and 120 seconds for a routine batch. Accepted at 20:58 UTC by the Claude session that implemented #14, under Nicolas's delegation. The maximum archive write was 0.721 seconds on Fedora and 1.235 seconds on Windows; maximum total batch time was 87.441 and 88.091 seconds respectively. The unchanged batch took 79.289 and 79.332 seconds without any archive write.

The archive contributes a short write phase only when something is incoming. Total time includes the existing 15-second stability check and up to 60-second handoff hold, plus reconnection and transfer. These runs measure the candidate; they are not a timed comparison with the old installed version. The limits cover this 5,000-note fixture and attachment size. Larger vaults or larger attachments need separate measurement. ZIP sizes exceed raw file bytes because of per-entry ZIP overhead across 5,005 files.

Earlier attempt and independent scheduler defect

The first run, i14-20260929T204359Z, incorrectly assumed two independently initialized vaults had nothing to exchange.
