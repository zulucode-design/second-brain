1. Executive Summary

The repository is one desktop application rather than a meaningful multi-package monorepo: SvelteKit/Svelte 5 renders the UI inside Tauri 2, a typed TypeScript facade invokes 111 Rust commands, Markdown files are canonical, and Tantivy plus SQLite embeddings are rebuildable local projections. The intended product is a local-first BASB Capture/Organize app with strict PARA filing. That core model is visible end to end and is not merely scaffolded.

The strongest areas are vault identity and relocation recovery, PARA reconciliation, ordinary note lifecycle indexing, credential migration into the OS keyring, SSRF-aware clipping/image retrieval, Notion publishing state, and narrow Tauri capabilities. All 19 Svelte components have a reachable render/import path. The frontend’s 111 invoke names exactly match the 111 backend registrations, and every API wrapper has a frontend source reference.

The original mutation-safety risk was adoption breadth rather than restore itself. PR #93 made restore transactional and introduced the shared bulk-mutation lease; issue #84 now consumes that contract for pre-backed-up, watcher-suppressed sidecar batches with terminal outcomes and projection convergence. At the original audited commit, WebDAV and editor navigation/shutdown also had unsafe paths; PR #90 replaces the save lifecycle, while PR #94 removes WebDAV from production.

ADR-0009's bundled, app-managed Syncthing sidecar over Tailscale is now implemented with explicit bilateral pairing and paired conflict-choice UX. Real supported-machine verification remains pending. Voice capture/transcription, capture-time similarity, semantic graph edges, and suggested-link promotion are beta commitments under ADR-0010. Distill and Express are correctly deferred.

State and persistence boundaries

  • Canonical: Markdown notes and selected in-vault metadata. CONTEXT.md explicitly defines Markdown as the source of truth.
  • Rebuildable projections: Tantivy keyword index and SQLite semantic chunks/pending queue; these are machine-local by design.
  • Machine-local: app config, the one-way WebDAV retirement marker, repair/relocation state, and indexes.
  • Vault-scoped: attachments, trash, history, holding area, shared retention settings, notebook icon map, and Notion registry/maps. The sidecar syncs this physical boundary; forced pre-sync backups include all of it.
  • Secrets: active provider keys and Notion credentials migrate to the OS keyring through secret_store.rs. Legacy WebDAV credentials are deleted only after cleaned configuration and pending stable IDs are durably recorded. Config is redacted and owner-only on Unix.

4. Detailed Feature Reviews

4.1 Startup and vault open

Trace: +page.svelte loads machine config and resolves the active vault → api.openVault → commands::open_vault/open_vault_path (commands.rs:307+) → vault structure and stable identity claim → relocation recovery/category reconciliation → Tantivy and semantic index open/reconciliation → watcher and semantic worker startup → config persistence/hotkey registration → vaultReady → AppLayout.

Strength This is a genuine recovery-oriented bootstrap, not a folder-open shortcut. Vault identity locking, relocation repair, category reconciliation, and rebuildable projections are conceptually aligned.

Finding +page.svelte:252–278 only exposes an active-vault restoration error on iOS; other failures are swallowed. The outer catch at +page.svelte:279–281 treats any config/startup exception as “First launch or no config.” Separately, commands.rs:3698–3713 defaults on unreadable or malformed JSON. This can hide corruption or permission failure behind an apparently fresh setup. Confidence: confirmed code path; user-visible result strongly inferred.

4.2 Capture and clipping

Quick capture trace: global hotkey/platform event → capture window → user text plus required PARA category → quick_capture_note → canonical Markdown creation → immediate keyword index + semantic enqueue → returned NoteEntry → window closes. A failed save leaves text in place.

Clipping trace: URL/category prompt in AppLayout → clip_web_page → backend URL validation and SSRF-safe fetch → readability/Markdown conversion and safe image proxy references → normal note persistence/indexing → active list refresh. The frontend test suite covers URL gating and visible backend failure text.

Missing The SPEC requires a semantic similarity check after capture with merge/edit choice. There is no such API, state, or UI path. Voice capture/transcription is also absent.

4.3 Editing, saving, and navigation

Historical save trace at audited commit 1c6f838: editor transaction/source input set editorDirty → debounce → serialize TipTap/source Markdown → queueSave → save_note → mutation lock → version/canonical Markdown update → Tantivy update and semantic enqueue. This is retained as the original evidence snapshot.

Fixed / verified Historical D-01 navigation and shutdown break. At 1c6f838, flushSave did not await persistence or enter the save queue, several navigation sources directly replaced active state, and the native close path did not await debounce or an in-flight save. Merged PR #90 replaces that behavior with one revision-aware SaveCoordinator, an EditorMutationBarrier, awaited and serialized main/secondary navigation, SHA-256 compare-and-swap writes, authoritative committed save/relocation outcomes, and a native save-before-close reservation/acknowledgement protocol that preserves close-to-tray behavior. Save rejection blocks the transition without falsely clearing dirty state. Focused regressions cover immediate navigation, rejection, close during debounce, and close during in-flight persistence. Final semantic review: APPROVED — no remaining blocking findings. OCI pnpm verify at implementation commit 0e558cb: Svelte 0 errors/0 warnings; frontend 64 passed/0 failed; Rust 500 discovered, 494 passed, 6 ignored, 0 failed; rustfmt, Clippy with warnings denied, and production build passed. See merged PR #90.

4.4 Search, graph, and derived state

Keyword and semantic search are separate and correctly named. SearchPanel uses a request generation guard to prevent stale result races and has explicit loading/error states. The semantic worker records durable pending notes, degrades when Ollama is unavailable, and uses a fixed versioned profile. semantic_search.rs:177–200 creates tables with IF NOT EXISTS but has no explicit schema/user version; because this DB is derived, deletion/rebuild is a viable recovery, making this a maintainability issue rather than an immediate blocker.

Graph data is built from explicit links only. Semantic edges, related-note suggestions, and promotion to explicit links do not exist. GraphView.svelte:188–191 only logs a load failure, leaving a blank graph. Sidecar-style conflict names are filtered using .sync-conflict- in commands.rs, but package D must define the actual sidecar convention and paired-resolution workflow.

4.5 Tasks and organization

Tasks are parsed from Markdown and remain part of their source notes. Completion, priority, and due-date updates identify both line and raw text to avoid blind mutation, then feed normal index/update behavior. The list and calendar layouts are real task views, not remnants of removed daily notes. TasksView.svelte:23–28 converts load failure to an empty array, so “backend failed” is visually indistinguishable from “no tasks.” Backend due-date validation at commands.rs:1957–1976 accepts any digit-shaped YYYY-MM-DD, including impossible calendar dates.

4.6 Trash, history, and backup

Deletion normally moves notes into .helixnotes/trash; note history is retained separately. History and trash are strong local safeguards. Backup scheduling is implemented in AppLayout.svelte:168–220, and creation/pruning is real.

“Whole-vault backup” is inaccurate: backup.rs:63–90 skips .helixnotes except optionally attachments, so trash, history, holding/shared metadata, and Notion maps are absent. WalkDir::filter_map(|e| e.ok()) silently omits traversal failures.

Restore is non-transactional. backup.rs:202–263 validates that the selected path is a ZIP in the configured directory and opens its central directory, but then deletes all visible vault content and attachments before iterating/extracting every member. A corrupt later member, disk-full condition, permission error, or process interruption leaves a partial vault with no rollback. The detached command at commands.rs:3105+ does not acquire note_mutation, stage/rename, rebuild projections, or refresh live UI state. Concurrent editor/import/watcher activity can compound the damage. Confidence: confirmed ordering and missing coordination; failure outcome strongly inferred.

4.7 Historical WebDAV sync at audited commit 1c6f838

Historical trace: settings stored per-vault provider/URL/user/password → password keyring → AppLayout scheduled on-open/on-change/interval calls → sync_now spawned a run → local scan + WebDAV PROPFIND → three-way comparison against a machine-local manifest → upload/download/delete/conflict copy → save manifest → rebuild keyword index → emit completion → frontend refresh behavior.

The following findings are retained as original audit evidence for the deleted implementation. PR #94 removes the client and every production invocation path; package D separately owns the future sidecar:

  • Traversal: href_to_relpath (sync.rs:399–438) percent-decodes a server-controlled href and returns the suffix without component validation. is_synced_relpath accepts values such as ../outside.md; write_local at sync.rs:129–135 calls vault.join(relpath). A malicious/compromised server—or a network attacker when HTTP is used—can write outside the vault.
  • Transport: WebdavClient::new at sync.rs:198–218 explicitly accepts http://; requests attach Basic Auth and note bytes (sync.rs:226–330). Credentials and content can cross the network in plaintext.
  • Coordination: sync does not acquire the normal note_mutation lock and is not transactional across files. It can race editor saves, import, restore, or reconciliation.
  • False success: local delete failure is discarded while the deleted count increments (sync.rs:650–653); save_manifest does not return a result and its failure cannot fail the run (sync.rs:75+, 747–748).
  • Unreadable can become deleted: scan_local silently skips directory-walk and file-read failures (sync.rs:153–170). A path present in the previous manifest but omitted from the scan is treated as locally deleted; if its remote ETag is unchanged, sync deletes the remote copy (sync.rs:657–687), allowing a transient local read failure to propagate as deletion.
  • Partial failure: a later operation can error after earlier writes. Normal completion/reindex/event behavior is then skipped, even though the vault changed.
  • Stale semantics: completion rebuilds Tantivy but does not reconcile semantic SQLite. Watcher muting prevents that projection from reliably learning incoming files through the normal external-change path.
  • Boundary drift: is_synced_relpath (sync.rs:142–151) includes Markdown, attachments, and notebook icons only. It omits trash, history, and .helixnotes/notion, contradicting SPEC §8 and undermining Notion’s vault-scoped registry/map model.
  • Conflict drift: WebDAV writes Name (conflict timestamp).md (sync.rs:116–127), while graph/Notion filters only recognize .sync-conflict- (commands.rs:1585–1589, notion/plan.rs:172–179). WebDAV conflict copies become ordinary indexed/publishable notes.
  • Missing safety promise: no forced backup runs before incoming bulk changes despite docs/SPEC.md §3.

4.8 Notion publication

The Notion implementation is materially stronger than a stub: token validation/storage, visible-page selection, four PARA databases, local identity maps, planning, moves/deletes/tombstones, paced publishing, progress summaries, polling, and reinstall page-adoption behavior are present. It is correctly one-way local-to-Notion.

The sidecar's whole-vault boundary includes the vault-scoped Notion registry/map, while credentials and publisher enablement remain machine-local. Its conflict convention prevents unresolved copies from entering publication. The marker written into Notion is not yet used for full database reclamation; comments describe this as deferred rather than pretending it is complete.

4.9 Import and external-file opening

import_obsidian starts a detached run without a compare-and-swap guard. do_import_obsidian toggles shared importing state but does not take note_mutation with RAII cleanup. vault/import.rs:205–208 ignores a failed write and increments files_converted. A successful event can therefore overstate conversion, and overlapping imports can race. There is no explicit semantic reconciliation or reliable live list refresh after watcher muting.

The external Markdown viewer is connected at the UI/event level but disconnected at the domain boundary. AppLayout.svelte:260–280 calls readNote(filePath) for an external path, while vault/operations.rs:66–81 permits only active-vault notes or trash entries. Tauri’s FS scope is expanded for OS-opened files, but read_note does not consume that scope-aware validator. Expected result: the viewer logs “Failed to open external file.”

5. Cross-Cutting Findings

5.1 Data integrity and transaction boundaries

The normal note command contract is good: serialize mutation, persist Markdown, update keyword index, enqueue semantic projection, and emit/refresh. The highest-severity defects are exceptions to that contract. Establishing one shared bulk-mutation coordinator—with mutation lock, preflight/staging, backup policy, projection reconciliation, and completion event semantics—would address several findings together.

5.2 Security posture

Positive evidence includes limited Tauri capabilities (the capture window receives a narrow set), OS-keyring credential handling, owner-only redacted config, safe external URL schemes, SSRF defenses for clipping/image proxy, vault/trash path containment, and stable vault identity locking. Lack of user authentication is appropriate for a local single-user desktop app and is not classified as a defect.

The WebDAV traversal and plaintext transport allowance are exceptions at a remote trust boundary and therefore disproportionately important. They should be resolved before asking alpha users to configure sync.

5.3 Error handling and observability

Search, settings operations, clipping, repair status, and quick capture generally surface useful state. Graph/tasks/startup/navigation often reduce errors to console logs, empty state, or no-op catches. Detached restore/import/sync commands rely on events, but partial failures do not consistently carry “vault changed; refresh/reconcile required” semantics. Logs exist, but there is no documented privacy/redaction policy or user-exportable diagnostic bundle.

5.4 Contract and type consistency

Command names are unusually clean: 111 TypeScript wrappers exactly match 111 Tauri registrations, with no wrapper lacking a frontend source reference. PR #90’s six lifecycle commands use typed save-before-close payloads. The broader event-based IPC contract still repeats string event names and several any-typed payloads across components/backend emitters with no generated/shared schema. Persisted Rust/TypeScript models are manually mirrored, increasing drift risk.

5.5 Product/specification consistency

docs/SPEC.md is explicit and internally detailed, but current code and user-facing identity have moved independently:

  • WebDAV authored in this repository versus a bundled sidecar/Tailscale topology that explicitly rejects authored sync.
  • Second Brain repository/identifier versus HelixNotes package/product/window names and https://helixnotes.com/latest.json updater (tauri.conf.json:3–15,39–43).
  • README’s local-AI positioning versus supported Anthropic/OpenAI/OpenAI-compatible writing providers (types.rs:127–143); semantic search itself remains Ollama-only.
  • Mobile code remains despite mobile being out of scope; multi-vault UI remains despite the one-vault decision.

5.6 Maintainability and performance

AppLayout.svelte and especially Editor.svelte concentrate many responsibilities. Theme lists/accent options/platform checks are duplicated between route layout/page, settings, command palette, and platform utilities. The production build succeeds but emits a chunk-size warning; the largest JS chunk is approximately 1.585 MB (476.77 kB gzip). This is not an alpha blocker for a desktop app, but editor/diagram code splitting should be measured on the target laptop.

11. Prioritized Remediation Plan

Phase 0 — Freeze risky alpha surfaces (immediate)

  1. Keep the selected sidecar unavailable outside development until package D closes. WebDAV is removed rather than hidden, and transactional restore shipped in PR #93.
  2. Use disposable vault copies for sync/restore/import testing; preserve a manual external backup.
  3. Open tracked issues for D-01 through D-06 with the evidence and exit criteria above. Do not bundle unrelated UI polish into these fixes.

Phase 1 — Eliminate P1 data loss and security risk

  1. Implemented / verified — PR #90 Unify navigation and shutdown: one awaited, revision/document-aware SaveCoordinator and EditorMutationBarrier now serialize editor mutation, navigation, relocation, vault switching, and native shutdown. SHA-256 compare-and-swap plus authoritative save/relocation outcomes prevent stale writes and false-clean state; focused regressions cover immediate navigation, rejected persistence, and close during debounce/in-flight save.
  2. Implemented / verified — PR #94 Remove WebDAV: the client, commands, registration, wrappers, active configuration, UI, controls, and schedulers are absent. Legacy fields and stable-ID credentials retire through an atomic, durable, retryable config-first migration without vault or remote I/O.
  3. Implemented / verified — PR #93 Make restore transactional: archive-wide preflight and sibling staging preserve the live vault until commit; a tested rollback path runs under the shared bulk-mutation lease, then reconciles projections and live UI.
  4. Implemented / verified — PR #93 and issue #84 Create a bulk mutation service: restore, import, and sidecar batches use one coordinator for exclusion, watcher suppression with guaranteed cleanup, reconciliation, and terminal success/changed-incomplete/failure outcomes.

Phase 2 — Resolve sync architecture and correctness

  1. Decision recorded — ADR-0009 / PR #94 The bundled sidecar over Tailscale is authoritative; WebDAV is removed from production.
  2. Implement and pin the bundled sidecar, app-owned lifecycle, authenticated pairing, checked interruption recovery, and one conflict naming/recognition contract.
  3. Implement conflict pairing/choice UI and exclude conflict copies consistently from list counts, search, graph, semantic index, and Notion until resolved.
  4. Define the complete synchronized vault set. Reconcile trash/history/Notion/shared settings with the machine-local boundary and add two-machine fixtures.
  5. Force and verify a backup immediately before applying incoming batches if that remains the SPEC safety strategy.

Phase 3 — Close correctness and observability gaps

  1. Fix Obsidian import write accounting, deduplicate runs, participate in bulk mutation coordination, and refresh both indexes/UI.
  2. Route external Markdown through a dedicated scope-aware read-only command; add inside/outside-vault tests.
  3. Make malformed config/startup/vault-open errors explicit and recoverable; distinguish missing config from unreadable/invalid config.
  4. Adopt atomic durable-write helpers for canonical notes and critical metadata. At minimum use same-directory temporary file, flush/sync as appropriate, atomic rename, and tested failure cleanup.
  5. Add visible graph/tasks errors and validate task due dates with a calendar parser.
  6. Correct backup wording/scope and surface skipped traversal failures.

Phase 4 — Establish an alpha verification gate

  1. Add Windows CI using the required pnpm test:rust wrapper; retain Ubuntu package verification. Pin package manager and runtime expectations.
  2. Add a small Tauri integration/E2E suite around: open vault → create/edit → immediate navigation → restart/read; search; trash/restore; transactional backup restore; legacy WebDAV retirement failure/retry; sidecar interruption once implemented; import failure.
  3. Generate or centrally define command/event names and payload types. Add IPC registration parity as an automated test.
  4. Add dependency/security/license checks and a packaged install/launch smoke test. Verify signed updater/release behavior before enabling the updater.
  5. Measure cold startup, editor interaction, and semantic search on the Linux laptop target; address the emitted bundle chunk warning only where measurements justify it.

Phase 5 — Align alpha scope and identity

  1. Decide whether voice, capture similarity, and semantic suggested links are alpha requirements. Implement them or move them to an explicitly named post-alpha milestone without implying completion.
  2. Finalize Second Brain versus HelixNotes product/package/binary/window naming, app identifier migration implications, homepage, and updater endpoint/key.
  3. Remove or formally support inherited mobile/multi-vault surfaces. Remove disconnected vaultState, stale comments, duplicated constants, and the /tests/ ignore rule.

12. Open Questions / Unverified Assumptions

  1. What is the first alpha’s declared feature contract? Is it a narrow Capture/Organize desktop alpha, or must it satisfy every current v1 commitment including voice, duplicate detection, suggested links, and two-machine sync?
  2. Resolved after the audit — sync authority: ADR-0009 reaffirms ADR-0002. WebDAV is removed from production through package B; package D implements the bundled Syncthing sidecar, explicit pairing, and interruption-safe reconciliation.
  3. Is sync mandatory for alpha? The sidecar implementation exists; if sync is in the alpha, its real Windows/Fedora protocol remains unconditional. D-02/D-05 are closed by WebDAV removal.
  4. What is the exact synced metadata boundary? In particular: trash, history, Notion identity maps, holding area, notebook icons, and shared retention settings.
  5. How should partial bulk failure be presented and recovered? A resumable journal, staging transaction, or explicit “changed but incomplete; reconciliation performed” contract is needed.
  6. Resolved after the audit — product identity: ADR-0011 makes Second Brain the sole user-facing product, retains io.github.zulucodedesign.SecondBrain, begins at 0.1.0-alpha.1, treats HelixNotes as separate, and disables the inherited updater pending a signed Second Brain channel.
  7. Are cloud writing providers intentional? If yes, README/privacy/offline claims should distinguish writing tools from Ollama-only semantic search and disclose data leaving the machine.
  8. Is mobile supported or merely inherited? Android-specific commands and UI exist, but mobile is out of SPEC scope and desktop is the advertised target.
  9. Does current hosted Linux CI pass at this exact commit? Yes for the original audit snapshot: GitHub Actions Verify run 34729884375 passed for exact audited HEAD 1c6f83887595f56c372c86d03a68558e97cbc23b, including pnpm verify, unsigned deb/rpm builds, and both desktop-entry checks.   10. How do Windows and Linux packaged builds behave live? Hotkeys, keyring retirement, updater, tray/autostart, file associations, external viewer, the sidecar, and restore require packaged runtime verification.
  11. What vault size is an alpha target? Semantic brute-force search is intentional for approximately 1k–10k notes, but startup/reconciliation/import/sync and graph performance need representative measurements.
  12. What durability guarantee is promised? If “local-first” implies crash-safe note writes, direct truncating writes should be elevated; if only application-level error recovery is promised, document that limitation.
