A few terms used below

These definitions make the rest of the report easier to follow.

Vault
The folder that contains all notes and the app's private metadata.
PARA
The four fixed categories: Projects, Areas, Resources, and Archives.
Holding area
The private .helixnotes/unfiled folder where notes with no category wait to be filed.
Reconciliation
The startup process that moves each note to the folder named by the category stored inside that note.
Ollama
A server that runs AI models locally or on another machine.
Tantivy index
The app's keyword-search database. It stores a note's path separately from the note file.

First, protect files and note data

These problems can alter the wrong file, overwrite content, or damage the structure of an existing vault.

SB-01. A crafted path can make the app alter a file outside the vault

Critical
What happens

The command that files a holding note only checks how the supplied path starts. It does not verify where the path really ends after resolving .. or a symlink.

Example

A path that begins inside .helixnotes/unfiled can contain steps that lead back outside it. The command then adds note metadata to the outside file and tries to move it.

Why it matters

A compromised app window or crafted symlink could corrupt or relocate a readable file that was never meant to be a note.

What should change

Resolve the real source path, prove it remains inside the holding folder, require a regular Markdown file, and reject symlink and traversal escapes before reading or writing.

Show code evidence

src-tauri/src/vault/operations.rs:1097-1111; IPC command at src-tauri/src/commands.rs:768-775. Compare the stronger path guards at operations.rs:21-41 and 90-96.

SB-02. Import from Obsidian can unfile every existing note

High
What happens

The importer scans every Markdown file in the active vault, not only new imports. It rebuilds the metadata with no category and then removes the category already stored in each note.

Example

A vault with 500 correctly filed notes is imported for Obsidian cleanup. All 500 notes lose Projects, Areas, Resources, or Archives in their frontmatter.

Why it matters

At the next startup, reconciliation sees uncategorized notes and can move all of them to the holding area. Links and familiar paths may also change.

What should change

Keep any valid existing category during import and add a regression test that imports and reopens an already-categorized note.

Show code evidence

src-tauri/src/vault/import.rs:18-29, 64-69, 337-347; category removal at src-tauri/src/vault/frontmatter.rs:198-209.

SB-03. Moving or restoring a note can replace another note without warning

High
What happens

The app moves a file directly onto its destination without first checking for a same-named note or choosing a safe alternate name.

Example

Projects/Plan.md is moved into Areas, where Areas/Plan.md already exists. On Linux, the existing Areas note can be replaced.

Why it matters

This is silent content loss during an ordinary PARA action. The overwritten note is not sent to Trash first.

What should change

Use the collision-safe naming logic for moves and restores, then test same-name moves between every category.

Show code evidence

src-tauri/src/vault/operations.rs:1002-1017 and 1238-1272. The reconciliation helper also has a check-then-move race at src-tauri/src/vault/para.rs:208-225. The basic move/restore risk existed before PARA, but PARA makes it a common workflow.

SB-09. Links and search still point to a note's old location after a move

High
What happens

The file moves and Quick Access is updated, but path-based wiki links and the keyword-search index are not.

Example

A link to [[Projects/Plan]] stays unchanged after Plan moves to Archives. Search may return the missing Projects path and omit the new Archives path.

Why it matters

The note appears moved in one part of the app but missing or broken in another until the index is rebuilt.

What should change

Treat a move as one operation that updates the file, category, links, Quick Access, and search index together.

Show code evidence

Move: src-tauri/src/vault/operations.rs:1002-1017. Rename already updates links at operations.rs:857-864. Command and search index: src-tauri/src/commands.rs:819-843 and src-tauri/src/search/mod.rs:307-342.

SB-14. One malformed category value can hide otherwise valid metadata

Medium
What happens

If an outside editor writes a category in the wrong YAML type, parsing can fall back to a blank metadata structure instead of rejecting only that field.

Example

category: 123 can cause the parser to lose the note's parsed ID, title, tags, pinned state, and dates in memory.

Why it matters

A single bad field should not make unrelated valid fields disappear.

What should change

Parse category separately or tolerate invalid category types while keeping the remaining metadata.

Show code evidence

src-tauri/src/vault/frontmatter.rs:8-17 and 45-52. Existing tests cover an unknown category string, not a category with the wrong YAML type.

SB-15. Vault startup can look successful even when filing work failed

Medium
What happens

Reconciliation skips or logs some unreadable notes, directory-walk failures, and failed moves. The app can continue opening the vault without telling the user that the job was partial.

Example

Three notes cannot be moved because of permissions. The vault still opens, and the user receives no clear list of the three notes that remain inconsistent.

Why it matters

The app's promise that note category is the source of truth is only reliable if failed repairs are visible.

What should change

Return a visible partial-failure report and test permission errors. Also avoid filtering out a vault simply because its own folder name begins with a dot.

Show code evidence

src-tauri/src/vault/para.rs:135-168, 194-199; caller at src-tauri/src/commands.rs:74-84.

Then, make the PARA workflow behave consistently

These issues make the main note-taking flow fail, hide notes, or create a state that the design says must never exist.

SB-04. New Note fails unless the app can guess a category

High
What happens

The global New Note action does not ask for Projects, Areas, Resources, or Archives. With no note open, it sends no category and the backend refuses to create the note.

Example

Open a new vault in All Notes and press New Note. The user sees a message telling them to pick a category, but the button itself never offered that choice.

Why it matters

The primary creation button fails at the first moment a new user is likely to try it. When another note is open, the app silently copies that note's folder instead of asking.

What should change

Make the global action show the four-category choice before it creates the note.

Show code evidence

src/lib/components/NoteList.svelte:396-432; AppLayout.svelte:333-336; TitleBar.svelte:123-127; rejection at src-tauri/src/vault/operations.rs:614-628; requirement at docs/SPEC.md:129-130.

SB-05. Unfile and Restore create states the PARA design forbids

High
What happens

Unfile moves a note to the vault root and removes its category. Restore also uses the vault root by default, which can leave the note's stored category and its folder in disagreement.

Example

Right-click a Project note and choose Unfile. It now has no category but sits in the normal vault, not in the private holding area reserved for that state.

Why it matters

The specification says every normal note must have exactly one category. The UI itself creates the state reconciliation is supposed to repair.

What should change

Remove or redefine Unfile, allow only PARA destinations, and restore a note to the category stored inside it. A failed metadata update must make the move fail or roll back.

Show code evidence

src/lib/components/NoteList.svelte:792-795, 1542-1548; src-tauri/src/vault/operations.rs:1002-1051, 1238-1272; rule at docs/SPEC.md:125-150.

SB-06. Notes waiting for a category cannot be opened

High
What happens

The holding queue shows clickable note rows, but the normal read command refuses to open files inside the app's metadata folder.

Example

A migrated note has a vague title. The user clicks it to inspect the content before deciding its category. Nothing opens; the error is only written to the developer console.

Why it matters

Users must file a note without being able to read what it says. Several context-menu actions on those rows fail for the same reason.

What should change

Add a narrowly validated read path for holding notes and show only actions that work in that view.

Show code evidence

List command at src-tauri/src/vault/operations.rs:1065-1082; read guards at operations.rs:25-79; UI at src/lib/components/NoteList.svelte:342-345, 366-380, 1184-1218.

SB-07. A category view hides notes stored in its subfolders

High
What happens

On desktop, a category view lists only Markdown files directly inside the category folder. It does not scan that category's subfolders.

Example

Projects/Launch/plan.md belongs to Projects, but it does not appear when the user clicks Projects.

Why it matters

The Projects count and list can look incomplete even though the files are correctly categorized.

What should change

Make category browsing recursive and select notes by the category stored in each note.

Show code evidence

src/lib/components/NoteList.svelte:357-359; non-recursive scan at src-tauri/src/vault/operations.rs:410-416.

SB-08. Moving a folder to another category does not really move its notes

High
What happens

The app moves the folder but does not change the category stored inside its notes. At the next startup, reconciliation follows the old categories and moves the notes back one by one.

Example

Move Projects/Launch into Archives. On reopen, its notes can return to Projects while losing the Launch folder structure.

Why it matters

The UI reports success, but startup later reverses the action and may flatten the user's organization.

What should change

Define folder-move behavior and update every contained note's category as part of the same operation.

Show code evidence

src/lib/components/Sidebar.svelte:397-410, 474-491; backend rename-only path at src-tauri/src/vault/operations.rs:1131-1164.

SB-12. The sidebar offers actions that can never succeed

Medium
What happens

Projects, Areas, Resources, and Archives still show Rename, Delete, and drag actions even though the backend correctly rejects those operations.

Example

A user chooses Rename on Projects. The menu implies the action is supported, but the backend refuses it. The sidebar can also create a top-level folder where New Note is then rejected.

Why it matters

The interface leads users into dead ends and makes fixed PARA rules look unreliable.

What should change

Hide invalid actions on the four roots and keep all user-created folders inside one of those categories.

Show code evidence

src/lib/components/Sidebar.svelte:252-283, 955-976, 1073-1135; backend root protection at src-tauri/src/vault/operations.rs:1114-1128.

SB-13. A large holding queue can skip notes while scrolling

Medium
What happens

The scroll calculation assumes every note uses one fixed row height. Holding notes have a second row of category buttons that the calculation does not count.

Example

After migrating many uncategorized notes, scrolling halfway through the queue can render the wrong slice of notes or hide later ones too early.

Why it matters

The problem appears exactly when a user has a large cleanup job and needs to trust that every note is visible.

What should change

Measure the complete row or turn off fixed-height virtualization for the holding queue.

Show code evidence

Virtual-row math at src/lib/components/NoteList.svelte:210-222; extra controls at 1330-1343 and 2394-2419.

Make AI status describe the server that will actually be used

The inference code and the health-check code disagree about authentication and current server identity.

SB-10. Password-protected Ollama servers are reported as offline

High
What happens

AI inference sends the optional Ollama API key, but the health check does not. An authenticated proxy rejects the check with 401.

Example

The configured model server is working and the saved key is correct. The unauthenticated check fails, marks it offline, and blocks the authenticated inference request before it is sent.

Why it matters

A configuration the Settings screen explicitly supports becomes unusable.

What should change

Use the configured credential for health and connection-test requests, then test against an authenticated mock server.

Show code evidence

Settings at src/lib/components/SettingsPanel.svelte:2240-2249; authenticated inference at src-tauri/src/ai.rs:57-69, 396-417; unauthenticated probe at src-tauri/src/ai_health.rs:180-188.

SB-11. The AI status can describe an old server

Medium
What happens

Saving new AI settings does not clear or refresh the current status. Two checks can overlap, and a slow result from the old endpoint can overwrite the newer result.

Example

Server A is down, then the user switches to working server B and checks again. B reports available first. A times out later and changes the shared status back to unavailable.

Why it matters

The app can block requests to a healthy current server because an older, unrelated check finished last.

What should change

Attach status to the full endpoint and a settings generation. Discard obsolete responses and refresh immediately after a relevant settings change.

Show code evidence

src-tauri/src/ai_health.rs:252-300; settings save at src-tauri/src/commands.rs:2334-2364; fast rejection at commands.rs:2645-2660.

Clean up behavior left behind by the redesign

These do not present the same immediate data risk, but they make the app and its specification harder to trust.

What remains untested

  • Live Ollama deployment: the deterministic socket matrix is complete, including authentication and stale responses. A real private/authenticated Ollama server remains untested.
  • Notion synchronization: v1 one-way and two-way synchronization are not implemented by this branch. Their implementation and live-service evidence belong to issues #12 and #13.
  • Linux native walkthrough: automated Linux verification passes, but the packaged Linux UI has not completed the same disposable-vault walkthrough performed on Windows.
  • Signed release pipeline: verification artifacts were deliberately built with --no-sign. The private updater key was not present, so signing and update installation were not exercised.
  • Bundle-size budget: the production build passes, but the largest client chunk is about 1.56 MB before gzip. Measure startup impact and set a deliberate budget before treating the warning as accepted.

Known test-suite fact: the Rust main and documentation targets currently contain zero tests. The 181 Linux tests and 169 Windows tests at the walkthrough head are green; the empty targets are recorded here so they are not mistaken for missing output.
