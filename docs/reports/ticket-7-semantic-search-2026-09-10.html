What changed

  • Added a deep Rust semantic-index module with an injected embedding boundary and production Ollama adapter.
  • Stored versioned note/chunk vectors and the pending embedding queue in machine-local SQLite via bundled rusqlite.
  • Added chunked embedding (1,500 characters, 200 overlap), cosine ranking, best chunk per note, result limits, and PARA-category filtering.
  • Connected create, save, duplicate, clip, file, rename, move, task-edit, trash, restore, notebook mutation, and external filesystem paths to indexing or reconciliation.
  • Added automatic startup reconciliation, 20-second retry, immediate wake on new work, profile migration, and exact-file corrupt-database recovery.
  • Added an explicit Keyword/Semantic choice in Search and status plus on-demand rebuild in Settings → Maintenance.
  • Made the supported Rust test launcher forward filters, release flags, and ignored-test flags while preserving the Windows test manifest.

Architecture and failure behavior

ConcernDecision
Search modesKeyword and semantic remain explicit, separate operations. Backend failure cannot disable literal search.
IdentityStable frontmatter ID when available; current path retained; path identity only for legacy ID-less notes.
Write pathSuccessful Markdown mutation enqueues SQLite work only. Network inference belongs to the worker.
Long notesOverlapping chunks; query returns one result per note using its highest-scoring chunk.
Model changesThe versioned embedding profile prevents incompatible comparisons and queues current Markdown for replacement vectors.
DamageSQLite corruption replaces only the exact derived database and its own sidecars. Permissions and ordinary I/O failures are not treated as corruption.

Manual verification gate

Do not mark ticket #7 complete from automated evidence alone. Verify these in a desktop build with Ollama 0.11.10+ and ollama pull embeddinggemma:

  1. Open a representative vault and watch Settings → Maintenance move from waiting to indexed.
  2. Create a note about a daily routine without the planned query words. Confirm semantic search for “how I structure my mornings” finds it while keyword search does not.
  3. Filter the semantic result to its PARA category, then to a different category.
  4. Edit the distinguishing concept, wait for the queue to settle, and confirm the new meaning ranks above the old one while unrelated low-confidence results are suppressed by the cutoff.
  5. Stop Ollama, edit/create a note, confirm note saving and keyword search still work, and confirm a waiting count appears.
  6. Restart Ollama without restarting the app; confirm the waiting count reaches zero and the new note becomes semantically findable.
  7. Trash and restore the note, confirming disappearance and return. Exercise notebook move/rename if time permits.
  8. Run Rebuild semantic index; confirm notes stay intact and results return after background processing.
  9. Repeat the core search/outage recovery path in the packaged Windows build before merge.

Explicitly deferred

  • Q&A/chat prompt UI (#8), capture-time similarity (#9), and suggested links (#10).
  • CLI provider architecture (#51); v1 semantic indexing deliberately uses the configured Ollama host independently of writing-provider choice.
  • Approximate-nearest-neighbour indexing; the recorded optimized exact scan does not justify it.
  • Combining keyword and semantic scores; each mode remains understandable and independently degradable.
  • Future threshold tuning/confidence display remains possible; issue #7 uses a 0.45 minimum cosine score calibrated against live EmbeddingGemma results. Title-only notes remain searchable, while low-confidence matches are suppressed.
  • Historical finding — resolved by issue #59: unexpected Markdown headings appeared in a note body during repeated Windows testing. Raw-file inspection confirmed the content was in Markdown; the follow-up traced the writer to an inherited frontmatter serializer that prepended the current title as an H1 on every non-empty save. Issue #59 removes that hidden body mutation and adds regression coverage across create, save, rename, and semantic rebuild.
