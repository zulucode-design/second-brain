Gate boundary

External-alpha product support is exactly Windows 11 x86-64 and Fedora 44 Workstation x86-64, as settled by ADR-0012 and issue #88. The Windows package for this gate is NSIS; the Fedora package is RPM. Existing Ubuntu, deb, and Windows Server jobs remain useful build infrastructure, but they do not establish product support. MSI, AppImage, macOS, Android, iOS, Ubuntu, and newer Fedora releases are outside this gate.

The tested capacity baseline is 10,000 notes in one logical vault. It is not an enforced maximum. All manual tests use disposable vaults. No verification step may mutate the production vault.

Candidate invalidation rule: final performance and package evidence names one commit. A later change to runtime code, dependencies, packaging, capabilities, or configuration invalidates the affected evidence and requires that row to be rerun.

Performance protocol and budgets

Use five runs per machine and report every sample, median, and maximum. Start from a stopped app with a valid, already-built local index unless the row explicitly measures rebuild. Measure user-visible completion, not native window creation. Background semantic indexing may continue after the core interface becomes interactive.

Instrumentation

Timings come from an opt-in probe that is inert unless SECOND_BRAIN_PERF_LOG names a file. The app then appends one JSON line per measurement with a wall-clock epochMs. Samples hold timings and counts only: no note content, title, path, or query. Every interval ends at the next painted frame (animation frame followed by a message-channel task), not at the native window or the data reply.

  • Fixture: node scripts/perf-fixture.mjs generate <vault> writes 9,999 notes across the four PARA roots with 19,998 explicit title links, plus one 5,000-word note (10,000 notes total).
  • Cold startup: node scripts/perf-startup.mjs <installed executable> <log> records a launch time, starts the app with SECOND_BRAIN_PERF_EXIT_AFTER_STARTUP=1, and waits for it to exit. The app writes startup-ready once session restoration has loaded the sidebar, note list, and last note and that frame is painted, then exits through its normal save-aware shutdown. The configuration must restore the 5,000-word note. A mark without the sidebar, note list, or an editable editor counts as a failed run.
  • Editor: each single-character key press without a modifier in the rich editor records editor-key from the input event timestamp to the next paint.
  • Graph: graph-render runs from graph view creation, which happens when the graph command opens it, until the frame after the first full-layout draw. It records node and edge counts.
  • Search: semantic-search runs from query submission after the input debounce until the ranked results are painted. The backend records semantic-backend with the embedding time and the local exact-scan time (database read, decode, cosine ranking) separately.
  • Summary: node scripts/perf-summary.mjs <log> prints every sample, median, nearest-rank p95, maximum, and verdict per budget. Raw logs are preserved with the evidence.

If a budget fails, preserve raw measurements and open a focused defect. Do not weaken a budget in the same change that fixes its failure.

Final package walkthrough

Run once on each supported machine against packages built from the same candidate commit. Record OS version, package filename and SHA-256, commit, start/end time, screenshots, and relevant diagnostic export.

  1. Install the package and launch it from the installed desktop/start-menu entry.
  2. Open a clean disposable vault; confirm all four PARA roots and no repair issues.
  3. Capture a note, edit it, navigate away immediately, reopen it, edit it again, and close the app immediately. Confirm both saves survived.
  4. Exercise keyword search, semantic search, graph, tasks, trash restore, note history, backup, and transactional restore.
  5. Clip a reachable web page and attach a local file. Confirm AI-offline mode leaves capture, editing, organization, and keyword search usable.
  6. Publish one disposable note to Notion when credentials are available; otherwise record the external-service block without using a production note.
  7. Display the malformed-config startup error from package F, then restore the disposable configuration.
  8. On Windows, perform #49's renamed-vault hotkey check and confirm the installed notification appears.
  9. Export diagnostics and run the planted secret/body/path assertions against the produced archive.
  10. Exit normally; confirm no app, sidecar, or watchdog process remains. Uninstall; confirm the disposable vault remains.
