Decisions to approve before coding

These choices remove ambiguity from the fixes. Each recommendation follows the settled PARA rule that every normal note has one category and the note itself is the source of truth.

1. Filename collision policy

Recommendation: choose a deterministic free name such as Plan 1.md. Never overwrite, and never make background reconciliation wait for a prompt.

2. Remove “Unfile Note”

Recommendation: remove it. Restore categorized notes to their recorded category; send only genuinely uncategorized legacy notes to the holding area.

3. Holding-note behavior

Recommendation: allow a read-only preview and “File under…” actions. Keep normal editing, drag, duplicate, rename, Quick Access, and new-window actions outside .helixnotes.

4. Cross-category folder moves

Recommendation: support them. Preserve the full subfolder hierarchy and update every contained note’s category as one recoverable operation.

5. Partial reconciliation failure

Recommendation: open the vault, but show a persistent report containing every affected path and reason. Do not reduce the failure to a log line.

6. New Note category choice

Recommendation: always require confirmation in a four-category picker. The current category may be preselected, but it must never be copied silently.

How every implementation slice runs

This is the same gate for a critical security fix and a low-priority cleanup. A slice is not finished because it compiles.

Agree on the seam

Confirm the public interface where behavior is observed. Do not add a private helper merely to make testing convenient.

Write one red test

Use a disposable vault or loopback server. The test must catch the exact reported symptom and leave real notes untouched.

Make the smallest fix

Implement only enough to turn that behavior green. Keep unrelated open issues and speculative abstractions out.

Run focused verification

Run the new test, its module suite, and any consumer-level check named in the work package.

Review after green

Run separate Standards and Spec review passes. Refactor only when the green behavior is protected, then rerun it.

Run the full gate

pnpm verify must pass before the slice is committed and its finding is marked fixed.

Test principle: assert user-visible outcomes through public interfaces. Do not add tests that merely grep component source or require exact prose in SPEC.md.

Phase 1: stop unsafe writes and data loss

Critical and high priority
1

Harden the holding-note path

Fixes SB-01 and creates the validator required by SB-06.

Critical
Red behavior

Traversal, an outside-pointing file symlink, a symlinked holding directory, a directory, and a non-Markdown file are all rejected before any byte changes. A valid direct holding note still files normally.

Implementation

Add one canonical holding-note validator. Resolve the holding root and requested file, prove containment, require a regular .md file, reject symlinks, and return the validated path used by subsequent reads and writes.

Focused command after the red test exists

cargo test --manifest-path src-tauri/Cargo.toml vault::operations::tests::file_unfiled_note_rejects_traversal_symlinks_and_non_markdown_targets -- --exact

Completion evidence

The outside sentinel file has the same hash before and after every rejected request. Run on Linux and repeat the filesystem-sensitive test on Windows before final approval.

2

Preserve metadata during parsing and import

Fix SB-14 first, then SB-02 on top of trustworthy parsing.

High
Red behavior
  • Numeric, array, map, boolean, and null category values become uncategorized without erasing valid ID, title, tags, dates, pinned state, or body.
  • Obsidian import of an already-categorized vault preserves category, ID, unknown frontmatter, body, and path after reopen/reconciliation.
Implementation

Deserialize category independently from the rest of frontmatter. During import, preserve an existing valid category instead of rebuilding every note with category: None.

Focused commands

cargo test --manifest-path src-tauri/Cargo.toml vault::frontmatter::tests::invalid_category_types_preserve_all_other_metadata -- --exact
cargo test --manifest-path src-tauri/Cargo.toml vault::import::tests::obsidian_import_preserves_category_and_survives_reconciliation -- --exact

Completion evidence

A synthetic categorized vault has an identical path/category manifest before and after import, except for intended Obsidian syntax normalization.

3

Create one no-clobber relocation interface

Foundation for SB-03, SB-05, SB-08, SB-09, and SB-15.

High
Red behavior

Two concurrent moves that choose the same destination can never replace one another. Both notes survive with distinct names on Linux and Windows.

Implementation

Replace scattered check-then-rename behavior with one deep relocation module. Its small interface owns destination validation, deterministic suffixing, no-clobber creation, explicit outcomes, and cleanup after failure.

Design constraint

Use a real no-clobber operation or reserve/create-new strategy. A second exists() check does not fix the race.

Test surface

Temporary filesystem fixtures through the relocation interface. Tests assert final files and contents, not internal helper calls.

4

Make note move and restore complete and recoverable

Fixes SB-03, SB-05, and SB-09 through the relocation interface.

High
Behavior
  • Only PARA destinations are accepted.
  • Moves and restores never overwrite.
  • “Unfile Note” is removed.
  • Restore follows recorded category; missing category goes to holding.
  • Metadata failure leaves the original note intact.
Complete move

Return old and new paths from the durable relocation, then update path-based wiki links, Quick Access, and the Tantivy entry. A stale derived index must be repaired or rebuilt and reported; source-note failures must roll back.

Red tests

All category pairs, same-name move and restore, metadata failure, note ID/body/history identity, link rewrite, Quick Access path, and search returning only the new path.

Focused command family

cargo test --manifest-path src-tauri/Cargo.toml vault::operations::tests::collision_never_overwrites_during_move_or_restore -- --exact
cargo test --manifest-path src-tauri/Cargo.toml commands::move_note_tests -- --exact

Completion evidence

A pre/post manifest proves both colliding notes remain, the moved note keeps its ID and body, links open it, Quick Access opens it, and keyword search contains no old path.

High

6

Require an explicit category when creating a note

Fixes SB-04.

High
Red behavior

Title bar, keyboard shortcut, All Notes, and fresh-vault “Create your first note” all open the same four-choice flow. Nothing is created before confirmation, and the open note’s folder is never inherited silently.

Implementation

Route every entry point through one note-creation workflow. It may preselect the active category/subfolder, but the user must confirm it. Keep the Rust backend rejection as the final invariant guard.

Focused verification

node --test tests/note-creation.test.mjs, then the packaged keyboard-only walkthrough. The Node test targets a real creation-flow policy used by the UI, not component source text.

Red behavior

8

Query categories recursively and lock sidebar rules

Fixes SB-07 and SB-12.

High
Category query

A category-root view recursively finds nested notes and filters by the category stored in each note. Ordinary subfolder browsing keeps its separately defined behavior.

Sidebar policy

The four roots cannot rename, delete, move, or reorder. User folders can only be created or moved beneath a category. Backend checks remain authoritative.

Red tests

Nested correct note included, wrong-category note excluded, metadata paths excluded, root actions disabled, user subfolder actions enabled, top-level creation rejected.

Focused commands

cargo test --manifest-path src-tauri/Cargo.toml vault::operations::tests::category_scan_is_recursive_and_filters_by_recorded_category -- --exact
node --test tests/para-ui-policy.test.mjs

Phase 3: make AI health identify the current server

High and medium priority
11

Authenticate probes and reject stale results

Fixes SB-10 and SB-11; completes the socket-test gap already tracked in GitHub issue #17.

High
Red socket matrix

Healthy, missing model, malformed body, 500, 401, refused, stalled, authenticated, blank-key, and deliberately reordered overlapping responses, all on ephemeral loopback ports.

Implementation

Send the same optional Bearer credential used by inference. Identify a probe by endpoint, model, and a secret-free settings generation. Saving relevant settings invalidates the old status, starts a refresh, and prevents an obsolete result from committing.

Fast-refusal rule

Block an inference request only when the unavailable status belongs to the exact current target. Unknown or stale status must not disable a healthy new target.

Scope boundary

Do not absorb the separate provider-enum work in GitHub issue #18 unless a red test proves it is required for these two findings.

Focused commands

cargo test --manifest-path src-tauri/Cargo.toml ai_health::tests::authenticated_ollama_health_and_connection_checks_send_bearer_token -- --exact
cargo test --manifest-path src-tauri/Cargo.toml ai_health::tests::ai_status_generation_rejects_stale_probe_results -- --exact
