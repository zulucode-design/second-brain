Scope and current result

Steps 1–2 of ticket #4, not the completed quick-capture feature

PR #25 claims the packageable app id io.github.zulucode-design.SecondBrain, provides Linux desktop entries, models registration status, and implements the XDG GlobalShortcuts portal handshake. It deliberately does not yet connect registration to application startup or implement the capture window, category picker, note creation, notifications, autostart, or settings UI.

Current review findings

What remains true after the 2 September follow-up

The hotkey is not yet active in the product. lib.rs declares the module with #[allow(dead_code)], but application startup does not yet call portal::register or consume its activation stream. This is expected for the stated steps 1–2 scope, but PR #25 must not be described as completing or closing ticket #4.

Low-confidence design observations:

  • Two desktop entries remain intentional: Tauri's product-named generated entry is hidden, while the app-id-named entry lets the portal resolve the application.
  • The shared fields could drift, so source and finished-package checks now enforce their relationship.
  • The earlier primitive-string concern is resolved by the validated ApplicationId type.

New regression safeguards · 2 September

SafeguardWhat it prevents
Validated ApplicationIdRejects empty, spaced, underscore, non-reverse-DNS, and empty-segment identifiers before portal use.
Canonical configured identifierPortal and desktop-entry APIs cannot silently use an unrelated string literal.
Source consistency testChecks Debian/RPM destination names and shared desktop fields against the configured id.
AppImage writer testProves first write, no-op for a current entry, and refresh after an AppImage move. Startup invocation remains step 3.
Finished-package CI checkBuilds an unsigned Debian package, extracts it, and byte-compares the installed app-id entry with the reviewed source entry.
