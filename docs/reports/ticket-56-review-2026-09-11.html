Ticket #56 — move provider secrets to the OS keyring

Reviewed 2026-09-11 against origin/main...feat/56-os-keyring, with origin/main fixed at fba068ccc3903fb1d18543bcd0c11d3912979d2b.

Security boundary

AI API keys and per-vault WebDAV passwords now live in the current user's native OS credential store. config.json keeps provider URLs, usernames, and other non-secret settings, but its normal persisted form is redacted. Future per-vault provider credentials can use the same stable vault identity and transactional write path.

Startup migrates existing plaintext only after every required keyring read succeeds. A partial keyring write is rolled back. If migration or the final config write fails, runtime credentials are cleared and the original plaintext file remains available for a later retry. Provider settings never fall back to that file.

Standards review

Resolved The first pass found that WebDAV keyring accounts were derived from a bookmark or path hash. That would orphan a password when a local vault moved. Per-vault accounts now use .helixnotes/vault_id, and opening a moved vault refreshes its path without changing its credential identity.

Resolved The first pass also found repeated credential enumeration and duplicate in-memory test stores. Credential enumeration now has one binding roster, and secret-store tests share one test adapter.

Resolved This report was missing in the first pass. It is now committed with the code as required by the repository's reporting policy.

Spec review

Resolved The first pass found that an unavailable keyring blocked every config write. Headless operation can now save non-secret settings while provider features stay unconfigured. If the old file contains an unmigrated credential, only that existing recovery value is carried forward on disk; it is not loaded into runtime state.

Resolved The first pass found that an unassociated legacy WebDAV password could be treated as migrated and erased. Migration now stops loudly unless every plaintext WebDAV password has a stable vault identity. The original file is left unchanged for a later retry.
