Ticket #193: callout-type menu reload verification

2026-10-02, Fedora laptop. Issue: the callout-type menu is built in the DOM, so Editor.hasPendingDraft() did not count it. A reload from disk (#191) while its Custom input was open replaced the callout, and Enter then dropped the typed type without a word.

Change

The editor keeps a reference to the menu it creates, and hasPendingDraft() counts the menu while it is attached to the document. The reload is then deferred, and retried every second as #191 already does for other menus, until the menu closes.

Automated checks

pnpm verify passes on the fix commit: 185 node tests and 633 Rust tests, plus check, clippy and build. tests/document-reload.test.mjs failed before the change and passes after it.

Live check

Release binaries built locally (pnpm tauri build --no-bundle) from main f8ecf73 and from the fix, driven under tauri-driver with a fresh vault and config. The note holds one [!note] callout. The script opens the type menu, chooses Custom, rewrites the note on disk, and waits 4 s, which is more than the 300 ms watcher debounce plus one retry.
