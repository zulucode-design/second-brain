Issue #89 — review fixes and manual verification

2026-09-28. The final Spec and Standards review of PR #162 at 6d4e99c found gaps that tests did not catch. This report records what changed and what was checked in the real app.

Findings fixed

FindingFix
Config, backups, and machine-local state still lived in the helixnotes directories that upstream HelixNotes also uses. Single-vault migration then rewrote that shared config.json (ADR-0011). app_dirs.rs keeps them under io.github.zulucodedesign.SecondBrain. A one-time move runs only when a Second Brain identifier directory already exists, so a HelixNotes-only machine is never touched. A marker stops it from repeating. A failed move blocks settings saves and retries next launch.
Compact layout followed window width, but each layout mounted its own Editor. Crossing the breakpoint destroyed the editor with an unsaved edit pending and reloaded stale content. Both layouts share one shell, so Editor stays mounted. The live TipTap view moves to the layout's new element. Entering compact layout with a note open shows the editor. The breakpoint is 768 px, matching app.css.
G4: configuration inside another sync product's folder was only warned about. vault/sync_product.rs refuses vaults inside OneDrive roots (Windows environment), Dropbox roots, and Nextcloud/ownCloud roots. The picker keeps its confirmation for products detection cannot see.
Tags depended on window width in compact layout. Tags always come from the backend, as in the full layout.
Theme id list and apply/dark logic were copied in four components. Moved once into platform.ts (applyTheme, isDarkTheme).
ADR-0001 still described .deb/AppImage entries and the helixnotes directory; leftover AppImage branch and "mobile" names. ADR-0001 amended; open_linux AppImage branch removed; comments renamed; Compact layout added to CONTEXT.md.
Picker offered "Back to current vault" after that vault failed to open. Hidden after a failed startup open; "Select previous folder" remains.

Manual verification (Fedora, release build, isolated XDG directories)

Driven with tauri-driver against src-tauri/target/release/second-brain, with XDG_CONFIG_HOME and XDG_DATA_HOME under /tmp/sb89, so no real configuration was read or changed.

ScenarioResult
Earlier Second Brain state: identifier directory exists, config and machine state in helixnotes, two vaults listed. Pass. Config and vaults/<id> moved; the helixnotes config is gone from the old place; one vault kept; the other vault's folder untouched.

HelixNotes-only machine: only helixnotes/config.json present. Pass. Vault picker shown; HelixNotes config.json byte-identical (sha256 d40fb123…).
Configured vault inside a folder containing a Dropbox .dropbox file. Pass. Open refused with "This folder is managed by Dropbox…"; nothing written into the vault; no offer to return to it.
Windows: %APPDATA%/%LOCALAPPDATA% move and OneDrive detection on an installed package. Not run live. Covered by the Rust unit tests that CI's windows-rust job runs; exercised by the next alpha harness run.
