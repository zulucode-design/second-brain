Manual protocol: interrupted 5,000-note transfer (#97)

Run on packaged builds of the same recorded commit on both machines, over Tailscale, using disposable copies of one vault that both machines have already paired. Stopping processes uses exact installed executable paths, never name patterns.

  1. Record the build commit, installer type (NSIS or MSI), app version, Syncthing version and device IDs, OS versions, and start time.
  2. On the sending machine, with the app closed: node scripts/sync-fixture.mjs generate <vault>. Its output records the sentinel hash.
  3. On the receiving machine, before syncing: node scripts/sync-fixture.mjs check <vault> must report matching: 0 and missing: 5000.
  4. Open both apps and press Sync now on both within 30 seconds. Repeat check on the receiver until matching is above 0 and missing is above 0. That proves the transfer began but did not finish.
  5. Run 1: on Windows, scripts\windows\sync-interrupt.ps1 -Action Stop -Target App. Run 2 (fresh vault copies): -Target Sidecar. Keep each JSON line it prints. The script searches both the NSIS and MSI install folders; pass -InstallDir for any other location. If it refuses because a process is unverified, rerun it from an elevated PowerShell.
  6. Within a minute, -Action Report must show no orphan Syncthing process after an app stop (the watchdog cleans it up). After a sidecar stop, the app's bounded restart may bring it back.
  7. Record what the UI shows. It must not report a clean or up-to-date outcome while check is incomplete.
  8. Restart the app normally, run Sync now on both machines, and repeat until the terminal outcome arrives.
  9. check on both machines must exit 0: 5,000 matching notes, sentinel present, no conflict copies, duplicate IDs, or strays. No manual file repair is allowed at any point.
  10. Confirm a helixnotes-pre-sync-*.zip exists for each interrupted run in the backup folder: the custom location if Settings sets one, otherwise %APPDATA%\helixnotes\backups on Windows and ~/.config/helixnotes/backups on Fedora. Then close the app and confirm -Action Report lists no processes.
  11. Attach the JSON lines, screenshots, and timestamps to #97 and update the D row above.

If a run fails, record the last check line, the terminal status, and the Report output, then open an implementation ticket. Do not change sync behavior inside this protocol.
