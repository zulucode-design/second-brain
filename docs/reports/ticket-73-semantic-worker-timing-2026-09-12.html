Ticket #73 — semantic worker timing test

Diagnosed and remediated on 2026-09-12 from main at 1c6f838, using the dedicated Windows checkout C:\Users\Nicolas\second-brain-issue62.

Diagnosis

The original test synchronized on the beginning of the first backend call, slept 100 ms, and expected the call count to remain one before a 200 ms retry interval. Under load, the test thread could resume after one or more legitimate intervals. A two-process focused Windows loop reproduced the exact failure reliably. Temporary boundary timestamps showed subsequent calls starting 449 ms and 281 ms later, proving that the cooldown was working.

Remediation

The observed test backend now blocks its first call while the test queues all extra wakes. The worker reports when its offline retry interval actually elapses, and the event stream must contain that boundary before the next backend call. This asserts causal ordering rather than elapsed wall time: scheduler delay cannot change the verdict, while a wake that bypasses cooldown produces a backend-call event in the wrong position and fails immediately.
