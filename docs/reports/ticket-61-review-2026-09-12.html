Ticket #61 — atomic directory-move manifests

Reviewed 2026-09-12 against origin/main...fix/61-atomic-directory-manifest, with origin/main fixed at c401f36df92bd60494a8a69574ef9afbab8be8c6 and implementation commit 3a8fa3a.

Diagnosis and remediation

The final manifest filename used to become visible when the file was still empty. A process killed before write_all completed therefore left an apparent recovery instruction that JSON parsing could not read. Every later vault open reported repair and skipped category reconciliation.

The writer now creates directory-move.json.tmp, writes and syncs the complete JSON there, renames it to directory-move.json, and syncs the transaction directory. Only the final name authorizes recovery. Startup removes an orphan temporary file because it never authorized a move.

For vaults affected by older binaries, startup discards a zero-byte final manifest. Under the old write order, no directory rename could have started before that manifest gained bytes. Nonempty malformed manifests still fail loudly and remain on disk rather than being guessed away.
