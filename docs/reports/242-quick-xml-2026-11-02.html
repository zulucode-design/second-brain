Kiro's handoff records one escaping difference between the versions and four older behaviors. No test pins any of them.

  • quick-xml 0.42 writes a carriage return in a replacement value as &#13;, where 0.41 wrote it raw. None of the twelve values can hold one. The API key is Uuid::new_v4().simple(), 32 hex characters, at sync_sidecar.rs line 100, and the other eleven are formatted numbers, addresses or fixed literals. This rests on reading the source, not on a run.
  • A document whose root end tag is missing at end of input is accepted and hardened.
  • A leading BOM is dropped from the output.
  • An unknown entity such as &bogus; passes through.
  • A comment inside a safety field puts the new value on each side of it, the same effect as the out-of-scope entity-reference case.

Kiro's sandbox compared both quick-xml versions on 26 inputs. 25 gave identical results; the one difference was a key containing a carriage return. The last four behaviors above were identical under both versions, so they predate the port. That comparison is information only.
