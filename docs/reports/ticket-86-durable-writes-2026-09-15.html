Ticket #86 — durable critical writes and explicit startup failures

Package F of #76, covering audit D-09 and D-11. Implemented on 2026-09-15 on fix/86-durable-writes from main at 8155213. An earlier attempt by another agent left no usable commits; this work started fresh.

What changed

durable::replace is the one crash-safe write: a same-directory temporary, sync_all, then atomic replacement (rename plus a directory fsync on Unix, MoveFileExW with write-through on Windows, retried for about 250 ms while another handle holds the destination). It serves note saves, import link rewrites, app config, vault UI state, shared vault settings, sync control state, the Syncthing config, vault identity repair, and the Notion registry, map, and last-run records. Three private copies of the helper were removed.

An absent config.json is a first launch. Unreadable, malformed, and incompatible files are distinct outcomes: the file is copied aside owner-only, vault entries that still parse are kept, no vault opens automatically, and the reason is shown in the vault picker. If the copy fails, settings saves are refused. A non-iOS active-vault open failure is shown in the picker and the app does not become ready.

Known limits

The damaged-config log line is dropped because config loads before the log plugin is registered; the picker message is the user-facing record. A crash between creating the temporary and replacing can leave a hidden .*.tmp that Syncthing may replicate — tracked in #99. No directory fsync on NTFS and no Windows ACL preservation, by design. The Syncthing sidecar restore still runs for the configured vault before the frontend's open, and its outcome is independent of vault readiness.
